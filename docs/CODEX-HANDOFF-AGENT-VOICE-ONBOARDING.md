## Current architecture and connected flows

**State and decisions.** React 19/Vite; `App.jsx` owns the browser state and UI bridges. `domain/state.js`'s `transition()` validates local mutations; `adapters/storage.js` keeps version 1 at `daywell.local-demo.v1`. Imported events, independent meal slots, plans and confirmed consumption remain separate. Plans do not count as intake. Recipe snapshots preserve historical nutrition/prices across reloads and source refreshes. Optional Postgres/Tiger Data saves pantry and chosen recipe records; browser state is still authoritative, not cross-device synchronized.

`domain/engine.js` checks diet/allergens, known cost and budget, pantry grams, equipment/cooking access, full meal duration, calendar conflicts, and dining facts. `discovery.js` separates feasible choices from drafts needing review. Ordering uses explicit priorities/preferences and conservative learned preferences, with cuisine variety; **weighted scoring remains disabled**. Daily nutrition goals are advisory progress, not a requirement that one meal supply the whole day. Old runtime labels/feature flags in `config.js` do not describe actual provider connectivity.

**Cook and Gemini.** `CookStart` in `FoodViews.jsx` accepts free text, editable ingredient grams, saved pantry or fridge-photo scanning (`/vision/ingredients`). `adapters/recipes.js` calls the existing `/recipes` endpoint with bounded preferences and constraints. `backend/meal_generation.py` defaults to `gemini-3.1-flash-lite`, generates **three** single-serving drafts, validates schema/equipment/time/positive allergen conflicts, caches/coalesces requests and bounds concurrency/errors. The endpoint also retains the old text-intent request contract; `/recipes/phrase`, `/recipes/substitute` and `/profile-patch` are preserved. Do not create a duplicate interpreter or replace Saurav's backend.

`More ideas` excludes previous names. On the last card the next text batch may be prepared ahead (`prepare: true`); photos wait until that batch is opened. A prepared **text** batch still costs a model call. Returning users with sufficient Backboard feedback may get saved-pantry preparation once a day. Prepared batches are consumed once; newly excluded recipe names are now filtered before display/photo generation.

**Photos.** `backend/meal_images.py` and `ui/format.js` implement dish-specific generated photos, accuracy checks, disk/cache reuse, Backboard photo indexing, bounded concurrent lanes and daily/warmup budgets. Configured defaults are Lite image generation with an image-model fallback. Campus images include dish/venue context and are labeled illustrations. `usePhotoGate` ranks ready photos first and releases the deck after 25 seconds even if generation fails; it does not permanently hide meals during an outage.

**Recipe review.** `RecipeReview.jsx` retains the existing one-click “Looks good — add to my plan” flow, optional edits, positive ingredient allergen/diet blocking, grocery-list additions and kitchen-equipment confirmation. It now dry-runs all proposed actions and checks meal eligibility **before** saving review/pantry/equipment/list changes. Failed planning leaves the dialog open; selecting a different meal in an occupied slot retains replacement confirmation. The underlying quick-confirm behavior is still a **user confirmation**: it can raise pantry quantities to recipe requirements, add missing equipment, and default an unmatched portion cost to the budget. These are not verified stock, ownership or product-price facts. Keep those assumptions visible; do not describe generated drafts as independently verified.

**Nutrition, pricing and cuisines.** `ingredient-matches.json` and `usda-browser.json` now contain **131 reviewed ingredient records**, not the older 14/20. Backend `usda.py`, frontend `ingredientNames.js`/`usdaFood.js`/`foodFacts.js` share reviewed identities/forms and bounded aliases/default assumptions. Nutrients derive from edible input grams and published per-100-g values, with correct Foundation energy precedence. Unknowns remain null; labeled subtotals never become complete intake totals. Nine curated Cook recipes have calorie/protein estimates. Prices use **13 reviewed QFC University Village products** via Kroger; ingredient-use cost and full-package purchase cost are separate, quote expiry is enforced, and chickpea drained-mass/unsupported-ingredient gaps remain unknown. No live quotes were refreshed in this audit.

Eleven cuisines, six taste preferences, preferred/disliked foods and avoided cuisines feed deterministic ordering and recipe personalization. Main's Flavors selector filters the current Cook deck; its grocery-session changes retain generated meals when switching modes and send stocked users directly to discovery from open slots. These teammate behaviors were preserved during integration. Six onboarding goals (`muscle`, `lean`, `healthy`, `energy`, `budget`, `easy`) suggest editable daily targets and pass goal hints to Gemini. Clearing a goal now removes its preset targets; saving an unchanged goal preserves customized target values.

**Backboard.** `mealFeedback.js` + `food_memory.py` record idempotent chose/logged/skipped signals under a browser UUID, with per-user assistants, cached deterministic summaries, recent meals, cuisine/taste/ingredient likes and repeated skips. Explicit profile choices and hard constraints win. This is anonymous scoping, not authentication. `storage.js` separately mirrors bounded food-preference snapshots via the existing shared demo `/preferences` endpoint; it does not copy the whole calendar/log/pantry state. Agent notes and photo-index memories are separate uses of Backboard. Do not confuse the old report's “zero memories at verification” with a missing implementation or today's account contents.

**Assistant.** `backend/agent.py` exposes `/assistant/agent`, schema-checks function calls and bounds model rounds. `adapters/agent.js` builds a compact snapshot and translates calls to existing state actions; `planTurn()` dry-runs the whole turn. `Core.jsx` hosts persistent-in-session chat, short formatted replies, confirmation, Undo, notes, navigation and recipe suggestion effects; `App.jsx` supplies `agentBridge`. Supported actions include local events/recurrences, busy/free overrides, preferences/goals, pantry/shopping list, meal slots/plans/logs, notes, navigation and remembered facts. Imported events remain read-only. Local changes can be undone; remote memories/feedback/reminder rows are not rolled back by browser Undo. `domain/nudges.js` computes dismissible schedule/grocery suggestions locally, without model calls.

**Voice and onboarding.** `backend/voice.py` serves `/assistant/transcribe` and `/assistant/speak`; configured defaults are Flash-Lite transcription and `gemini-3.8-flash-lite-tts` with `gemini-3.8-flash-tts` fallback, Aoede/WAV/cache. `adapters/voice.js` records 16 kHz WAV, detects pauses, transcribes, plays replies in parts, and falls back to browser speech synthesis. The assistant supports hands-free follow-up and spoken confirmation. `Onboarding.jsx` offers chips or “Just tell me”; voice now merges with selected chips and previews the result locally. `preview: true` also prevents server-side `remember` writes even if the model requests one. Saving applies the profile once and sets `onboarded`; skipping leaves the preview unsaved. Backend agent/voice imports now occur after dotenv loading so model/voice overrides take effect.

**Calendar and reminders.** `calendar.js`, `CalendarViews.jsx`, `mealWindow.js` and the picker provide Today/agenda, week/month views, open breakfast/lunch/dinner slots, local events/tasks/notes, recurrence-aware ICS, holidays/busy overrides and conflict checks. Apple uses the signed local Swift/EventKit helper after consent. Google uses existing read-only OAuth/primary-calendar import; connected providers can refresh on focus/five-minute intervals. Automatic next-meal context refreshes on load/opening Let's eat, respects an open manual window and uses the next busy commitment; “No further commitment” removes the automatic time cap. Manual windows remain available. `saveEvent` now preserves validated local activity kinds, fixing task completion after calendar refresh.

`photon/remind.mjs` is a **separate existing Node/Spectrum iMessage poller**, backed by `photon_contacts`, `photon_plans`, `photon_sent`: 30-second polling, five-minute lead, chosen-meal reminders and per-send timestamps. Profile phone enrollment, sender-line handshake and schedule/open-slot sync already exist. This audit did not start the poller, enroll a number or send a message. App reminder sync and grocery nutrition requests now use the same-origin Vite proxy, fixing the old hardcoded-backend CORS issue on `:5181`.
