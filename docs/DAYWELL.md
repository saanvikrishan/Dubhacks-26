# Daywell

A working React/Vite app for planning a day and finding food around UW. This implementation is in `fridgemate/` on `codex/daywell-calendar-workflow`, based on the current team commit `cd6d653`. Existing backend files and the separate local `daywell/` work are preserved.

## Run

Requires Node 22.12+ and npm. Apple Calendar additionally requires macOS and Apple Command Line Tools (`xcrun swiftc`).

```sh
cd fridgemate/frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Open **http://127.0.0.1:5173/**. Keep this terminal running while using the preview. If the port is occupied, use the Local URL Vite prints. A `file://` link to `index.html` will not run the app.

```sh
npm test
npm run build
npm run lint
```

The production bundle is in `fridgemate/frontend/dist/`. `vite preview` or static hosting serves the frontend only; the Apple Calendar API is currently attached to the local development server.

## Three distinct pages

- **Today:** the next calendar activity, side-by-side Cook / Eat at school entry points, a full day agenda, the saved meal, and confirmed intake with Undo.
- **My Plan:** week/month calendar, overlapping event columns, all-day events, selected-day list, local activities and tasks, and planned meals. Imported events are read-only. Open a meal block and choose **Change this meal** to revise that slot.
- **Food:** separate picture-card decks. Drag/swipe left to pass, right to choose a Cook recipe or navigate to Google Maps for a UW venue. Tap the picture or details button for more. Arrow keys and visible buttons provide alternatives to dragging. Mood, priority, diet, budget, equipment, groceries, time and optional nutrition goals are editable. There is no Compare both mode in the UI.

**Weighted scoring remains off.** Explicit rules check feasibility; named comparisons order eligible recipes. The preserved team weight configuration is dormant and cannot be activated without validation.

## Apple Calendar

Use **Connect calendar → Connect Apple Calendar** and approve the macOS prompt. The local EventKit helper reads events from calendars available on this Mac. macOS calls its permission “full access”; this helper implements reads only and has no event-writing code or API.

A refresh reads approximately 90 days around the selected date. Select another date in My Plan and refresh to load its surrounding range. The UI flags dates outside the loaded range. Refresh manually after changes in Apple Calendar. Event copies persist in this browser; no calendar data is sent to Gemini, Photon or a remote server. Disconnect removes imported copies while preserving local activities and meals.

An **.ics export** can be imported instead (Calendar → File → Export → Export). Recurrence, exceptions, IANA/embedded time zones, all-day events and dated VTODO tasks are supported within bounded import ranges. Imports are snapshots, not subscriptions. Apple Reminders is not connected; tasks can be added locally or imported from ICS.

## Food data and the current “agent”

The Cook library has **nine curated recipes** with illustrative nutrient values and cost estimates. They are fixtures, not generated by a language model. Rules reject conflicts with calendar time, ingredients/quantities, equipment, diet/allergens and strict budget. Preferred food, protein, price or full activity time determines order. Goals compare with confirmed intake and do not secretly change ranking.

Eat at school uses five real UW locations: Husky Den, Center Table, By George, Local Point and Cultivate. Official [UW HFS location pages](https://hfs.uw.edu/eat/locations-and-hours/), [Husky Deals](https://hfs.washington.edu/eat/husky-deals/) and [UW building coordinates](https://www.washington.edu/maps/?json=campusmap.get_locations) back menu links, published prices/hours and straight-line distances from the **UW HUB**. Open locations are shown first by default. Station hours and availability can differ; venue suitability is not a verified dish/allergen match.

Current numeric ratings, routed travel times and exact dish nutrition are **not loaded**. Maps supplies routes/reviews; UW links supply nutrition/allergen lookup. A venue visit reserves time without inventing consumption or nutrient values. Four older fictional eat-out fixtures remain solely for existing saved records and domain compatibility; they are not offered in the active UW deck.

Food pictures are representative AI illustrations, labeled in the UI. See [asset provenance](docs/ASSETS.md).

## Verify the core loop

Use an isolated browser profile/origin for testing rather than resetting someone's existing data.

1. Set a noon meal window of 65 minutes, next commitment 13:15, vegetarian, and adequate sample groceries.
2. Food → Cook: inspect the tofu bowl (60 minutes total, 520 kcal / 27 g protein, illustrative) and choose it. A meal block appears in My Plan. Intake stays unchanged.
3. Adjust the window to 50 minutes. The saved tofu meal remains and shows why it no longer fits. Swipe to another recipe and confirm the named replacement.
4. Log the amount actually eaten. Half a tofu bowl adds 260 kcal and 13.5 g protein; a plan alone adds nothing. Undo reverses the most recent creation, edit or removal. The meal log also supports direct editing/removal.
5. Reload to verify persistence. Add a busy class across the meal window; conflicting Cook recipes are rejected without relaxing constraints.
6. Eat at school: inspect a real UW venue's distance, menu, hours and data limits. Swipe right for walking directions. Adding a visit does not log food.

Data lives in this origin's localStorage (`daywell.local-demo.v1`). `localhost` and `127.0.0.1` are different origins. Existing v1 records migrate without deleting meals or logs. Reset affects only this browser origin, including its calendar copies. Multiple tabs are not synchronized.

## Team handoff

- UI: `fridgemate/frontend/src/App.jsx`, `src/ui/CalendarViews.jsx`, `src/ui/FoodViews.jsx`, shared dialogs in `src/ui/Core.jsx`, and `src/ui/redesign.css`.

- Verification: [test and browser report](docs/VERIFICATION.md).

Gemini, Atlas and Photon remain unconnected. The assistant supports bounded local commands. The team still needs reviewed nutrition/recipe data; a live places provider for ratings/routed time; authenticated server ownership and storage; then server-side Gemini/Atlas/Photon credentials and actual adapters. See [architecture and configuration](docs/ARCHITECTURE.md). No orders, payments, messages or external calendar writes are implemented.
